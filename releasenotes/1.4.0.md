# Yautbox 1.4.0 — Polymorphic Batches & Tracing

Released on August 15, 2026.

[Full diff: v1.3.0...v1.4.0](https://github.com/maximiliysiss/yautbox/compare/v1.3.0...v1.4.0) · [All release notes](README.md)

Yautbox 1.4.0 adds heterogeneous batch enqueueing and extensible tracing, and improves PostgreSQL processing and migration reliability.

## Highlights

- Added `IPolymorphicOutboxService` for enqueueing mixed payload types in one batch. Messages are routed by their concrete runtime type, and returned identifiers preserve input order.
- Added tracing hooks for enqueue, fetch, handle, persist, cleanup, and cancellation operations through `IOutboxTracer` and `IOutboxTraceScope`.
- Added `SetTracing<T>()` to the outbox infrastructure builder. The built-in default tracer remains a no-op, so tracing has no setup requirement.

## PostgreSQL

- Messages without `scheduled_at` are now treated as immediately available by using `-infinity` in scheduling comparisons.
- Added an index on active messages by type, id, and effective schedule time to improve polling performance.
- Added corrective migrations that safely remove the earlier failed scheduling migration and create the replacement index concurrently.
- Concurrent application starts now serialize outbox migrations with a retried PostgreSQL advisory lock, waiting up to ten minutes instead of failing immediately when another instance owns the lock.

## Processing and observability

- Added tracing spans and failure reporting around message enqueueing, fetching, handling, result persistence, cleanup, and cancellation.
- Documented the at-least-once delivery model, unordered processing, and the requirement for idempotent handlers.
- Fixed the `OutboxMessageId` source-generation configuration to register the System.Text.Json converter only once.

## Breaking changes

- `IOutboxProvider.AddAsync<T>` now accepts `IReadOnlyCollection<AddRequest<T>>` instead of a single identifier plus `IReadOnlyCollection<OutboxMessage<T>>`. Each request carries its own identifier, enabling heterogeneous batches. Custom provider implementations must update this method.
- Null payloads passed to enqueue operations are rejected with `ArgumentNullException`.

- Added end-to-end processing benchmarks for the PostgreSQL and in-memory providers, including multi-host PostgreSQL scenarios.
- Added a dedicated benchmark CI job and Markdown benchmark reports.
- Added coverage for handler tracing, polymorphic enqueueing, provider behavior, and concurrent migrations.
